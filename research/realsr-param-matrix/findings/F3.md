## 2) Typical training settings used in public RealSR-related code

### 2a. Official RealSR (LP-KPN) paper + released Caffe code

| Setting | Paper value | Released code value | URL | Confidence |
|---|---|---|---|---|
| Patch size | **192×192** | (HDF5 pre-cropped) | https://arxiv.org/html/1904.00523v1#S5 | High |
| Mini-batch | **16** | **64** in `LP-KPN.prototxt` | paper vs https://raw.githubusercontent.com/csjcai/RealSR/master/Train/LP-KPN.prototxt | High (discrepancy noted) |
| Optimizer | Adam (β1=0.9, β2=0.999, ε=1e-8) | Adam, momentum 0.9 / 0.999 | https://raw.githubusercontent.com/csjcai/RealSR/master/Train/LP-KPN_solver.prototxt | High |
| LR | fixed **1e-4** | fixed **1e-4** | same | High |
| Iterations | **1,000K** (paper) | **100,000** (`max_iter` in released solver) | paper vs solver.prototxt | High (discrepancy noted) |
| Loss | L2 (Euclidean) multi-scale | EuclideanLoss on 3 Laplacian levels, ratio 1:1:1 | paper + repo | High |
| Augmentation | rot 90/180/270 + hflip | — | paper | High |
| Weight decay / solver | — | weight_decay 1e-4, lr_policy fixed, snapshot 5k | solver.prototxt | High |
| Framework | Caffe (+ Matcaffe test) | Caffe | https://github.com/csjcai/RealSR | High |

**Practical takeaway:** paper protocol is the most cited (192² / B=16 / Adam 1e-4 / 1M iters). Public solver is a reduced (100k) variant with larger batch. For a modern reimplementation, use paper settings.

### 2c. Common protocol matrix for RealSR finetune / reimplementation

| Hyperparam | Common values | Recommendation for RealSR V3 ×2 |
|---|---|---|
| Patch (LR) | 48–72 (synth) / 96–192 (RealSR paper) | **96–192 LR** (RealSR images are large; paper uses 192² LR) |
| Patch (HR) | 192–320 | ×2: **192 LR → 384 HR**, or paper-style 192 LR only if following original |
| Batch | 4–64 | **8–16** fits modern GPUs for ×2 on 192² |
| LR | 1e-4 (PSNR) / 1e-5 (GAN) | **1e-4** PSNR stage |
| Optimizer | Adam / AdamW | Adam β=(0.9, 0.999) |
| Iters | 100k–1M | **300k–500k** for finetune; **1M** from scratch |
| Loss | L1 or L2 (PSNR); +VGG/GAN for visual | L1 for metric SOTA |
| Augment | hflip + 90° rot | same |

## 3) Common PSNR/SSIM ranges on RealSR ×2

**Important protocol notes (affects absolute numbers):**
- V1: HR same resolution as LR (pseudo-scale) → slightly different absolute levels than true ×2.
- V2: HR same resolution as LR, expanded test (100 scenes).
- **V3: true different HR/LR resolution** — this is the modern benchmark; official README **does not publish ×2**.
- Metric almost always **Y-channel PSNR/SSIM** (or RGB train / Y test per V3 note).
- Crop border / alignment residual / whether bicubic-resized LR is used as input all shift numbers by ~0.1–0.5 dB.

### Observed / reported ranges (strong PSNR-oriented methods)

| Setting | ×2 PSNR (Y) | ×2 SSIM | Source | Confidence |
|---|---|---|---|---|
| Bicubic (V1) | ~32.6 | ~0.907 | RealSR paper Table 3 | High |
| Mid CNNs (VDSR/SRResNet, RealSR-trained, V1) | ~33.6–33.7 | ~0.917–0.919 | same | High |
| Strong CNN (RCAN, RealSR-trained, V1) | ~**33.9** | ~**0.922** | same | High |
| LP-KPN official (V1) | **33.90** | **0.927** | same | High |
| LP-KPN official (V2) | **33.49** | **0.917** | GitHub V2 table | High |
| Strong modern methods on RealSR-like paired real data (PSNR-oriented) | typically **~33.5–35.0** | **~0.91–0.94** | synthesis of V1/V2 + later literature | Medium |
| GAN / perceptual models (ESRGAN-style) | often **<33** (PSNR tradeoff) | lower | general SR literature | Medium |

## 4) Caveats for the param matrix

1. **V3 ×2 is under-documented officially.** The README V3 table omits ×2. Any ×2 number must cite the paper that produced it and its protocol (V1/V2/V3, Y vs RGB, train split).
2. **Batch/iter discrepancy** in official RealSR code vs paper — cite both if reproducing.
3. **Modern “real-world SR” code (Real-ESRGAN / BSRGAN / SwinIR-RW)** trains on **synthetic DF2K+OST with blind degradation**, not RealSR pairs. Use those configs as *training hyperparam templates*, not as RealSR-pair recipes.
4. Residual misalignment in RealSR pairs means absolute PSNR is not comparable to DIV2K-style bicubic benchmarks.
