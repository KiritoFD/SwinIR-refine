# F1 — Optical forward model for RealSR-style pairs

**Audience:** engineers who already train residual-CNN/transformer SR on RealSR-like paired data.
**Scope:** invertibility, spatially varying PSF / aberrations, sampling-theoretic recoverability, architecture/training consequences.
**Access date of all quotes:** 2026-09-13.
**Primary sources used:** Cai et al. ICCV 2019 RealSR (arXiv:1904.00523), Wang et al. Real-ESRGAN (arXiv:2107.10833), Zhang et al. BSRGAN (arXiv:2103.14006), Köhler et al. SupER (arXiv:1809.06420). Direct Wikipedia/optics pages and WebSearch were unavailable; field-curvature / chromatic-aberration / Nyquist claims are marked with lower confidence where not explicitly quoted from a fetched primary source.

---

## 1) Correct forward model for RealSR-style pairs (not bicubic)

### C1.1 — Two-camera zoom pairing is *not* a single fixed linear operator

| Field | Value |
|---|---|
| **Claim** | RealSR pairs are captured by changing focal length on a DSLR, not by applying a known bicubic kernel. The LR and HR images are *separate optical captures* of the same scene, with different FoV, optical-center shift, exposure, and residual distortion. The forward map from scene irradiance to each image is therefore a different camera operator; after registration, the residual LR←HR map is a *learned / spatially varying* degradation, not a global `k`. |
| **Quote** | “we build a real-world super-resolution (RealSR) dataset where paired LR-HR images on the same scene are captured by adjusting the focal length of a digital camera. … Considering that the degradation kernels are naturally non-uniform in our dataset, we present a Laplacian pyramid based kernel prediction network (LP-KPN), which efficiently learns per-pixel kernels to recover the HR image.” |
| **URL** | https://arxiv.org/html/1904.00523 (arXiv:1904.00523, Cai et al., ICCV 2019) |
| **Date** | 2019-04-01 (paper); accessed 2026-09-13 |
| **Confidence** | **High** |

### C1.2 — Classical synthetic forward model (what RealSR is *not*)

| Field | Value |
|---|---|
| **Claim** | The standard textbook degradation used for DIV2K-style training is `x = D(y) = [(y ⊛ k) ↓_r + n]_JPEG`. Bicubic is a special case of this with a fixed interpolant and zero noise. Real-ESRGAN and BSRGAN both start from this equation and then expand it because “real-world degradations are usually too complex to be modeled with a simple combination of multiple degradations.” |
| **Quote** | “the ground-truth image y is first convolved with blur kernel k. Then, a downsampling operation with scale factor r is performed. The low-resolution x is obtained by adding noise n. Finally, JPEG compression is also adopted… `x = D(y) = [(y ⊛ k) ↓_r + n]_JPEG`” |
| **URL** | https://arxiv.org/html/2107.10833v2 (Real-ESRGAN); see also classical form `y = (x ⊗ k) ↓_s + n` in https://arxiv.org/html/2103.14006v2 (BSRGAN) |
| **Date** | 2021-08-17 / 2021-09-30; accessed 2026-09-13 |
| **Confidence** | **High** |

### C1.3 — RealSR-like paired model: two *distinct* optical paths

| Field | Value |
|---|---|
| **Claim** | For RealSR-style pairs the physically correct statement is closer to two captures of a latent scene `S`: `x = D_L(S) + n_L` (short focal length) and `y = T(D_H(S)) + n_H` (long focal length, then a registration warp `T` and luminance map). Thin-lens optics is the stated basis: `1/f = 1/u + 1/v`, magnification `M = v/u ≈ f/u` for `u ≫ f`, so image size scales with focal length. |
| **Quote** | “The DSLR camera imaging system can be approximated as a thin lens. … Therefore, h₂ is approximately linear to f. By increasing the focal length f, larger images with finer details will be recorded in the camera sensor.” Registration explicitly corrects “shift of optical center, variation of scaling factors, different exposure time and lens distortion.” |
| **URL** | https://arxiv.org/html/1904.00523 (§3.1–3.3) |
| **Date** | 2019-04-01; accessed 2026-09-13 |
| **Confidence** | **High** for the two-path / thin-lens statement. **Medium** for writing the full equation as `x = D_L(S)+n_L, y = T(D_H(S))+n_H` — that exact factorization is our engineering synthesis of Cai’s description, not a verbatim formula in the paper. |

### C1.4 — Invertibility implication (severely ill-posed, non-injective)

| Field | Value |
|---|---|
| **Claim** | The map `S → x` (and even the registered `y → x`) is many-to-one: optical blur + sensor integration + demosaic + ISP + noise destroy high-frequency content. No unique inverse exists. SR is therefore a *set-valued inverse*; any single deterministic `f(x)` must pick one member of that set using a prior. PSNR-trained networks implement an approximate MMSE/MAP mean and over-smooth; GAN/diffusion heads sample the posterior. |
| **Quote** | “Since SISR is a severely ill-posed inverse problem, learning image prior information from the HR and/or LR exemplar images plays an indispensable role in recovering the details from an LR input image.” |
| **URL** | https://arxiv.org/html/1904.00523 (§1) |
| **Date** | 2019-04-01; accessed 2026-09-13 |
| **Confidence** | **High** for ill-posedness. **High** that non-injectivity follows from blur+downsample+noise (standard linear-algebra argument: rank-deficient operator). |

### C1.5 — RealSR’s residual operator is *not* the same operator as the capture operator

| Field | Value |
|---|---|
| **Claim** | After registration, what a supervised SR net learns is `x ≈ R(y)` where `R` is a *composite residual* that includes: residual misregistration, DoF change with focal length, chromatic / geometric differences between the two optical states, and (for RealSR specifically) that both images already passed through camera ISP. This is why “models trained on simulated data become less effective when applied to practical scenarios.” |
| **Quote** | “the blur kernel varies with the depth in a scene and the DoF changes with the focal length.” … “SISR models trained on simulated data become less effective when applied to practical scenarios.” |
| **URL** | https://arxiv.org/html/1904.00523 |
| **Date** | 2019-04-01; accessed 2026-09-13 |
| **Confidence** | **High** |

## 2) Spatially varying PSF / field curvature / chromatic aberration

### C2.1 — RealSR kernels are depth- and field-dependent, not shift-invariant

| Field | Value |
|---|---|
| **Claim** | Cai et al. explicitly state that RealSR degradation kernels are “naturally non-uniform” and that blur “varies with the depth in a scene” (circle of confusion / DoF). They therefore use per-pixel kernel prediction (LP-KPN) rather than a single global kernel. |
| **Quote** | “Considering that the degradation kernels are naturally non-uniform in our dataset, we present a Laplacian pyramid based kernel prediction network (LP-KPN), which efficiently learns per-pixel kernels…” … “For LR images in our RealSR dataset, the blur kernel varies with the depth in a scene and the DoF changes with the focal length.” |
| **URL** | https://arxiv.org/html/1904.00523 |
| **Date** | 2019-04-01; accessed 2026-09-13 |
| **Confidence** | **High** |

### C2.2 — What a network must estimate to invert a spatially varying PSF

| Field | Value |
|---|---|
| **Claim** | To invert a space-variant degradation the network must estimate (or implicitly condition on) a *field*: a per-pixel (or per-patch / low-rank) kernel map `K(i,j)`, or equivalent latent codes for local blur + local noise + local warp. RealSR LP-KPN predicts a tensor `T ∈ R^{(k×k)×h×w}` and applies `I_H^P(i,j) = ⟨K(i,j), V(I_L^A(i,j))⟩`. Kernel prediction has better “efficiency, interpretability and generalization capability” than free-form pixel synthesis. |
| **Quote** | “The KPN takes the I_L^A as input and outputs a kernel tensor T ∈ R^{(k×k)×h×w}… The reshaped per-pixel kernel K(i,j) is applied to the k×k neighborhood of each pixel… to reproduce the HR output.” |
| **URL** | https://arxiv.org/html/1904.00523 (§4) |
| **Date** | 2019-04-01; accessed 2026-09-13 |
| **Confidence** | **High** |

### C2.3 — Field curvature / lateral chromatic aberration: not in RealSR’s equations, but implied by real lenses

| Field | Value |
|---|---|
| **Claim** | Petzval field curvature makes the best-focus surface curved rather than planar → PSF grows with field radius even for a flat scene. Lateral chromatic aberration makes magnification wavelength-dependent → channel-dependent spatial scale and edge color fringes. Both are *space-variant* and *channel-dependent*. RealSR’s registration only does a global affine + luminance fit (`α, β, τ`); it does not model radial PSF growth or per-channel scale. So residual field-dependent blur and color misregistration remain in the pairs. |
| **Quote** | (indirect) Registration solves `min_τ ||α C(τ ∘ I_L) + β − I_H||_p^p` with a single global affine `τ` and global luminance `α,β`. RealSR cites circle-of-confusion and DoF as the physical reason for kernel variation, but does not write a field-curvature or CA model. |
| **URL** | https://arxiv.org/html/1904.00523 (§3.3, refs 51–52 on CoC/DoF) |
| **Date** | 2019-04-01; accessed 2026-09-13 |
| **Confidence** | **Medium.** Field-curvature / CA as *the* cause of residual space-variant blur in RealSR is standard optics but was **not** explicitly stated in the fetched text. Treat as engineering prior, not a quoted RealSR claim. |

### C2.4 — What happens if the network assumes shift-invariance

| Field | Value |
|---|---|
| **Claim** | A shift-invariant model (single global `k`, or a fully convolutional residual stack that never conditions on image coordinates / depth / field position) can only apply one inverse filter everywhere. On RealSR this yields: (a) over-sharpened corners and under-sharpened center (or vice versa, depending on aperture/DoF), (b) ringing where the assumed kernel is too sharp for the local true PSF, (c) residual blur where the assumed kernel is too soft, (d) color fringes left untreated. Empirically, RCAN trained on RealSR *does* improve over simulated-data RCAN (so some of the mismatch is learnable from content), but LP-KPN’s explicit per-pixel kernels are sharper — evidence that *explicit* space-variance helps. |
| **Quote** | “Training an SISR model which directly transforms the LR image to the HR image, as done in most of the previous CNN based SISR methods, may not be the cost-effective way. We therefore propose to train a kernel prediction network (KPN) which explicitly learns an individual kernel for each pixel.” |
| **URL** | https://arxiv.org/html/1904.00523 (§4, Figs. 1e–1f) |
| **Date** | 2019-04-01; accessed 2026-09-13 |
| **Confidence** | **High** that shift-invariant assumption is suboptimal on RealSR (paper’s own ablation argument). **Medium** on the specific failure-mode list (engineering synthesis). |

### C2.5 — Synthetic degradation models still assume shift-invariant kernels

| Field | Value |
|---|---|
| **Claim** | BSRGAN and Real-ESRGAN expand the *kernel family* and *noise family* dramatically, but both still use **global** convolutional kernels (isotropic/anisotropic Gaussian, generalized Gaussian, plateau, sinc). They do **not** model space-variant PSF. Training on them therefore prepares a net for “unknown but shift-invariant” blur, not for RealSR’s field-dependent blur. |
| **Quote** | Real-ESRGAN: “We adopt Gaussian kernels, generalized Gaussian kernels and plateau-shaped kernels, with a probability of {0.7,0.15,0.15}.” BSRGAN: “the blur is approximated by two convolutions with isotropic and anisotropic Gaussian kernels.” |
| **URL** | https://arxiv.org/html/2107.10833v2 ; https://arxiv.org/html/2103.14006v2 |
| **Date** | 2021-08-17 / 2021-09-30; accessed 2026-09-13 |
| **Confidence** | **High** |

### C2.6 — Spatially variant degradation is a known open axis in the literature

| Field | Value |
|---|---|
| **Claim** | BSRGAN’s related-work cites Cornillere et al., “Blind image super-resolution with spatially variant degradations” (ACM TOG / CGF 2019) as a distinct line of work. This confirms the community treats space-variance as a first-class issue, not an edge case. |
| **Quote** | “Cornillere et al. [8] propose an optimization procedure for joint blur kernel and HR image estimation by minimizing the error predicted by a trained kernel discriminator.” (ref [8] = “Blind image super-resolution with spatially variant degradations. ACM TOG, 38(6):1–13, 2019.”) |
| **URL** | https://arxiv.org/html/2103.14006v2 (§2.2, ref 8) |
| **Date** | 2021-09-30; accessed 2026-09-13 |
| **Confidence** | **High** for the citation’s existence and framing. Full text of Cornillere et al. was not fetched. |

## 3) Sampling theorem: recoverable information vs hallucination

### C3.1 — Nyquist bound: only sub-pitch, non-aliased content is information-theoretically recoverable

| Field | Value |
|---|---|
| **Claim** | Let the sensor pitch be `p` (LR pixels). Scene spatial frequencies above `f_Nyquist = 1/(2p)` (in the LR sampling grid) are not representable. After optical low-pass / pixel aperture / OLPF, energy near and above Nyquist is attenuated; what remains may alias if the pre-filter is weak. **Information-theoretic SR is only possible for:** (i) frequencies *below* Nyquist that were attenuated but not destroyed (deconvolution / Wiener-type recovery, noise-limited), and (ii) multi-frame / sub-pixel-shifted samples (not the RealSR single-image setting). Content that never reached the sensor cannot be “recovered” from a single LR image — any appearance of it is prior-driven synthesis. |
| **Quote** | (physics, not quoted from fetched papers) Standard Shannon-Nyquist + camera pipeline argument. Supporting material from Real-ESRGAN: ringing/overshoot are caused because “the signal is bandlimited without high frequencies.” |
| **URL** | https://arxiv.org/html/2107.10833v2 (§3.3) for the bandlimit remark |
| **Date** | 2021-08-17; accessed 2026-09-13 |
| **Confidence** | **High** for the Nyquist principle (textbook). **Medium** for applying it *quantitatively* to RealSR pairs — RealSR does not publish MTF curves for the Canon 5D3 / Nikon D810 + 24–105 f/4 used. |

### C3.2 — Real cameras *do* pre-filter; that is why bicubic ≠ optical

| Field | Value |
|---|---|
| **Claim** | Real capture includes a non-ideal anti-alias chain: finite pixel aperture (box/area integrate), optical MTF (diffraction + aberrations), optional OLPF, then demosaic (Bayer) which itself is a band-limiting / interpolation step, then ISP sharpening which *reintroduces* high-frequency energy (overshoot). BSRGAN models the sharpening overshoot with sinc kernels; Real-ESRGAN does the same. This is why “ideal bicubic + AWGN” is the wrong training distribution. |
| **Quote** | “The main cause of these artifacts is that the signal is bandlimited without high frequencies. These artifacts are very common and usually produced by a sharping algorithm, JPEG compression, etc.” … Real-ESRGAN “employ[s] sinc filters in the synthesis process to simulate the common ringing and overshoot artifacts.” BSRGAN models “processed camera sensor noise via reverse-forward camera image signal processing (ISP) pipeline model.” |
| **URL** | https://arxiv.org/html/2107.10833v2 ; https://arxiv.org/html/2103.14006v2 (§3.3) |
| **Date** | 2021; accessed 2026-09-13 |
| **Confidence** | **High** that ISP / bandlimit / overshoot matter and are modeled by both papers. **High** that pixel aperture + OLPF exist in real cameras (standard camera design). **Medium** on exact OLPF presence in the specific RealSR bodies (many modern cameras omit OLPF). |

### C3.3 — When is SR “hallucination”?

| Field | Value |
|---|---|
| **Claim** | Operationally: if the residual high-frequency energy in `x` at a location is below the noise floor (or was killed by the optical MTF), then any HR detail the network produces there is drawn from the learned prior `p(HR texture | LR context)`, not from the measurement. Metrics that average over the image hide this: a net can score well by getting “plausible grass” wrong at the pixel level. Perception–distortion tradeoff is the formal frame. |
| **Quote** | (from BSRGAN, citing Blau & Michaeli) “the PSNR-oriented BSRNet model tends to produce oversmoothed results due to the pixel-wise average problem, the perceptual quality-oriented model is preferred for real applications.” |
| **URL** | https://arxiv.org/html/2103.14006v2 (§5, refs to Blau & Michaeli perception-distortion) |
| **Date** | 2021-09-30; accessed 2026-09-13 |
| **Confidence** | **High** that perception–distortion tradeoff applies. **Medium** on the exact noise-floor threshold criterion (not computed in these papers). |

### C3.4 — RealSR pairs are *better aligned to recoverable content* than bicubic pairs, but still not “free lunch”

| Field | Value |
|---|---|
| **Claim** | Because LR and HR are separate optical captures, the LR image contains whatever the short-focal-length system actually resolved (optics + sensor + ISP). That is a *more honest* measurement of recoverable content than bicubic of an HR image (which invents a perfectly band-limited, noise-free downsample). But: DoF at short focal length is *larger* (deeper), so some regions in LR may actually be *sharper* relative to their pitch than a naive “HR÷4 blur” would imply; and the HR “ground truth” itself has its own aberrations and noise. |
| **Quote** | “the aperture was adjusted according to the depth-of-field (DoF). Basically, the selected aperture value should make the DoF large enough to cover the scene and avoid severe diffraction.” … “the blur kernel varies with the depth in a scene and the DoF changes with the focal length.” |
| **URL** | https://arxiv.org/html/1904.00523 (§3.2, §4) |
| **Date** | 2019-04-01; accessed 2026-09-13 |
| **Confidence** | **High** for DoF/focal-length coupling. **Medium** for the “LR sometimes relatively sharper” implication (optics; not measured in paper). |

### C3.5 — Real-data benchmarks show simulated-data rankings do not transfer

| Field | Value |
|---|---|
| **Claim** | Köhler et al.’s SupER lab dataset (real optical sampling, four resolution levels, sensor noise, motion, coding) found that methods ranked top on simulated data can be surpassed on real data. This is direct evidence that the *sampling/noise physics* of the capture changes the solution ranking, not just the aesthetics. |
| **Quote** | “One interesting result is that top-performing methods on simulated data may be surpassed by others on real data.” |
| **URL** | https://arxiv.org/abs/1809.06420 |
| **Date** | 2018-09-17 / rev 2019-06-16; accessed 2026-09-13 |
| **Confidence** | **High** |

## 4) Practical implications that change architecture / training

These are action items, not slogans. Each is tied to a claim above.

### C4.1 — Prefer kernel-prediction / filter-flow heads over pure pixel synthesis on RealSR

| Field | Value |
|---|---|
| **Implication** | If you are on RealSR (or any zoom/focus-stacked pair set with residual space-variant blur), add a **per-pixel or low-rank kernel head** (KPN / LP-KPN / predictive filter flow). It is cheaper than a huge residual stack and matches the physics. LP-KPN used Laplacian-pyramid multi-scale kernels so a `k×k` kernel at each of 3 pyramid levels gives an effective `4k×4k` receptive field at full res. |
| **Evidence** | C1.2, C2.1, C2.2. |
| **Confidence** | **High** |

### C4.2 — Condition on field position, or use coordinates / FoV embeddings

| Field | Value |
|---|---|
| **Implication** | Shift-invariant CNNs/transformers cannot distinguish “center pixel” from “corner pixel” given the same local appearance. Add: (a) normalized image coordinates (CoordConv / implicit position channels), (b) optional radial-field embedding, (c) if available, EXIF (focal length, aperture, focus distance) as a global token. This lets a shared backbone learn a *smooth* kernel field without per-image kernel estimation. |
| **Evidence** | C2.3, C2.4, C2.5. |
| **Confidence** | **Medium–High.** Strongly motivated by optics + RealSR’s non-uniform kernels; not an ablation reported in the fetched papers. |

### C4.3 — Do not train on bicubic-only if you deploy on RealSR-like images; but RealSR-only also under-generalizes

| Field | Value |
|---|---|
| **Implication** | Two failure modes: (1) bicubic-trained nets fail on real LR (degradation mismatch). (2) RealSR-trained nets overfit to *that* Canon/Nikon + 24–105mm + registration pipeline. Real-ESRGAN’s own tables show RealSR-trained models are *not* best on all real sets (e.g. they are strong on RealSR-Canon/Nikon but weaker elsewhere). **Recipe:** pretrain on a wide synthetic degradation family (BSRGAN-style shuffle + high-order + ISP noise), then fine-tune / multi-task on RealSR pairs. |
| **Quote** | “the captured data is only constrained to degradations associated with specific cameras, and thus could not well generalize to other real images” (Real-ESRGAN on RealSR-style data). Real-ESRGAN NIQE: RealSR-Canon 6.87 vs Real-ESRGAN 4.59 (lower is better). |
| **URL** | https://arxiv.org/html/2107.10833v2 (§2, Table 1) |
| **Date** | 2021-08-17; accessed 2026-09-13 |
| **Confidence** | **High** |

### C4.4 — Expand the degradation family: ISP noise, JPEG, sinc overshoot, random order

| Field | Value |
|---|---|
| **Implication** | If you synthesize pairs, at minimum: (i) dual blur (iso + aniso Gaussian, plus generalized Gaussian / plateau / sinc), (ii) random resize among nearest-with-shift, bilinear, bicubic, down-up, (iii) Gaussian + Poisson + JPEG + reverse-forward ISP sensor noise, (iv) **random shuffle of blur/resize/noise order**, (v) optional high-order (2nd pass) degradation. This is the BSRGAN + Real-ESRGAN consensus. |
| **Quote** | BSRGAN: “randomly shuffled blur, downsampling and noise degradations… reverse-forward camera image signal processing (ISP) pipeline model and RAW image noise model.” Real-ESRGAN: “second-order degradation process… sinc filters to model common ringing and overshoot artifacts.” |
| **URL** | https://arxiv.org/html/2103.14006v2 ; https://arxiv.org/html/2107.10833v2 |
| **Date** | 2021; accessed 2026-09-13 |
| **Confidence** | **High** |

### C4.5 — Treat the inverse as posterior sampling, not deconvolution

| Field | Value |
|---|---|
| **Implication** | Because the operator is non-injective (C1.4) and most high-frequency content is prior-supplied (C3.1, C3.3): (a) a single L1/L2-trained deterministic model will over-smooth (pixel-wise average); (b) a GAN/diffusion head will hallucinate plausible but possibly incorrect detail; (c) if you need *metric* fidelity (e.g. document OCR, scientific), constrain the hallucination (edge/data consistency loss: re-degrade the output with an estimated kernel and match `x`, or use a faithfulness-weighted objective). Real-ESRGAN trains L1 first (Real-ESRNet) then adds GAN — that order is not accidental. |
| **Quote** | “First, we train a PSNR-oriented model with the L1 loss. The obtained model is named by Real-ESRNet. We then use the trained PSNR-oriented model as an initialization of the generator, and train the Real-ESRGAN with a combination of L1 loss, perceptual loss and GAN loss.” |
| **URL** | https://arxiv.org/html/2107.10833v2 (§3.4) |
| **Date** | 2021-08-17; accessed 2026-09-13 |
| **Confidence** | **High** |

### C4.6 — Alignment is part of the forward model — audit it, do not ignore it

| Field | Value |
|---|---|
| **Implication** | RealSR’s global affine + luminance registration (`α, β, τ`, Lp robust, 5 iterations) leaves residual local misalignment, especially away from the optical center. That residual acts as *extra* space-variant blur in the training pairs. Practical checks: (i) compute residual optical-flow / NCC maps on pairs and mask or down-weight high-residual patches, (ii) prefer center crops (RealSR already crops around optical center because “distortion at 24mm is more difficult to correct”), (iii) consider a learned local-warp refinement stage before the SR backbone. |
| **Quote** | “We first import the images with meta information into PhotoShop to correct the lens distortion. However, this step cannot perfectly correct the lens distortion especially for the region distant from the optical center. We thus further crop the interested region around the center of the image, where distortion is not severe and can be well corrected.” |
| **URL** | https://arxiv.org/html/1904.00523 (§3.3) |
| **Date** | 2019-04-01; accessed 2026-09-13 |
| **Confidence** | **High** |

### C4.7 — Architecture sketch consistent with the optics

| Field | Value |
|---|---|
| **Implication** | A practical residual-CNN/transformer layout for RealSR-like data: **(1)** optional coordinate + EXIF embedding concatenated to input; **(2)** shared trunk (residual blocks or Swin/transformer) producing features; **(3)** two heads — (a) a kernel/filter head (per-pixel `k²` or basis coefficients over a small dictionary of kernels, multi-scale like LP-KPN), (b) an optional residual image head for non-convolutional residual (noise, JPEG, color); **(3)** apply kernels as a local linear layer (dynamic convolution / filter flow); **(4)** loss = Charbonnier/L1 + frequency-band consistency + (optional) GAN/perceptual after a PSNR warm-up. For transformers: replace global attention at full res with windowed attention + a low-res global branch so the kernel field can be estimated cheaply. |
| **Evidence** | C2.2, C4.1–C4.5. |
| **Confidence** | **Medium–High.** Composition of established pieces; not a single paper’s exact architecture. |

### C4.8 — Evaluate with optics-aware splits, not only PSNR/SSIM on full images

| Field | Value |
|---|---|
| **Implication** | Report metrics stratified by **field radius** (center vs mid vs corner) and by **local contrast / texture**. A shift-invariant model will look fine on average and fail at the edges. Also keep a “hallucination probe”: high-frequency energy ratio `E_HR(E_out)/E_HR(E_in)` and a re-degradation consistency score. |
| **Evidence** | C2.4, C3.3, C4.6. |
| **Confidence** | **Medium.** Recommended engineering practice; not an ablation in the fetched papers. |
