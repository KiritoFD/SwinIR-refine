# F2 — Misregistration: solve alignment, don’t just reweight the loss

**Access date:** 2026-09-13  
**Audience:** Mod-SwinIR residual-SR on RealSR V3 ×2 (406 pairs, RTX 4070 8GB)  
**Question:** What *actually* lifts PSNR when LR–HR pairs are misregistered?

---

## Executive answer

Misregistration is a **correspondence** problem. Affine registration (what RealSR ships) cannot remove non-rigid residual; L1/L2 then compute gradients on the wrong pixels and the optimum is blur.  
**What works on real zoom pairs:** (1) coarse/window-level **deformable offsets** when residual is large; (2) **train-only** alignment that disappears at inference (Mimicked-LR / OF-in-loss) when residual is small–moderate.  
**What fails:** CXLoss/CoBi as the main reconstruction loss; vanilla per-point DCN; loss reweighting without correspondence.

## 2. Methods that *explicitly align* — with real-pair ablations

### 2.1 Deformable / offset prediction (strongest large-misalign evidence)

| Method | Idea | Real-pair numbers | URL / date / conf. |
|---|---|---|---|
| **SDAN** (Mei, Ye, Huang, ICME 2021) | Squared (window-level) offsets instead of per-point DCN; Cross-Packing Attention for offset RF; train with downsampled HR as reference, infer with (X,X). | **SR-RAW ×4:** Bicubic 20.15 · SRResNet+CX 26.88 (RAW) · DCN 20.91 · SDCN 26.41 · +CPA 27.25 · +flip **30.53** PSNR / 0.870 SSIM / 0.133 LPIPS. RAW vs RGB +1.48 dB. | https://arxiv.org/abs/2104.00848 · code https://github.com/MKFMIKU/SDAN · 2021 · **high** on SR-RAW; **not reported on RealSR** |
| **EDVR / TDAN / BasicVSR-style DCN** | Video/burst: flow + DCN. Proven, but *not* ablated on RealSR/AIM SISR pairs in those papers. Burst SR (BSRT) uses FG-DCN on misaligned RAW bursts (NTIRE’22 winner) — multi-frame, not zoom-pair. | BSRT: https://arxiv.org/abs/2204.08332 (2022) | **high** for multi-frame; **N/A** for RealSR SISR |

**Design rule from SDAN ablation:** vanilla per-point DCN **fails** on optical zoom (20.91 dB). Coarse window offsets + large offset receptive field are required. Flip-aug on the reference is cheap and large (+3 dB in their stack).

## 3. What failed or is unnecessary (on real zoom pairs)

| Approach | Evidence it fails / is unnecessary | URL / date / conf. |
|---|---|---|
| **CXLoss / CoBi as main recon loss** | On RealSR→synthetic transfer, **2–3 dB worse** than plain L1 (SwinIR Set5 CX 21.56 vs L1 23.51; CoBi 20.65). Color shift + washout. NRQM can look OK while NIQE/PI and visuals are bad. Keep CX only if residual is SR-RAW-scale. | https://arxiv.org/html/2410.05410v1 Table 2 · 2024 · **high** |
| **Vanilla per-point DCN** | Optical-zoom ablation: 20.91 dB vs 30.53 full SDAN. Wrong granularity + too small offset RF. | SDAN Table 2 · 2021 · **high** |
| **Plain L1/L2 on unaligned pairs** | SDAN formalization + Mimicked: L1 is the *worst* RealSR baseline when residual exists; produces blur. | both papers · **high** |
| **Loss reweighting only (amp/HF/conf)** | Your own 6k ablation: ≤0.03 dB (noise). Literature agrees: without correspondence, weighting the same wrong pixels does not add information. | brief.md + this review · **high** |
| **Affine-only offline registration as the *complete* fix** | RealSR ships affine; later papers still need DCN / mimicked / OF. | multiple · **high** |
| **Pseudo-GT / dual-module alignment stacks** | Error accumulation; usually ≤ Mimicked on RealSR. | Mimicked · medium |
| **Auxiliary-LR dual-zoom** | “Limited to small and simple shifts”; fails complex misalign (Mimicked’s words). | Mimicked intro · medium–high |
| **Expecting PSNR on RealSR *test* to measure alignment** | Official test is itself misaligned → PSNR/SSIM unreliable; use aligned synthetics or NR metrics for A/B. | Mimicked §4.1 · **high** |

## 4. One implementable recipe (small transformer residual-SR, 8 GB, RealSR V3 ×2)

**Goal:** remove residual correspondence error **in training only**; keep Mod-SwinIR inference graph unchanged.

### Primary: Train-only Mimicked-LR (or OF-in-loss lite)

1. **Keep** official RealSR V3 ×2 pairs (already affine-registered). Do **not** rely on CXLoss/CoBi.
2. **Per batch:**  
   - `HR_hat = resize(HR, LR)` (same geometry as GT).  
   - Estimate flow `ψ = OF(HR_hat, LR)` with a frozen light flow net (e.g. RAFT-Small / PWC, 1 forward, no grad).  
   - `LR_w = warp(LR, ψ)`; mask `m` from flow validity.  
3. **Alignment head (train-only, ~0.5–2M params):**  
   - Inputs: concat(HR_hat, LR) → few convs (or GAP guidance vector from LR) → residual degradation transfer → `Mim_LR`.  
   - Decoder uses **1×1 convs only** (no stride) so geometry of HR_hat is preserved.  
   - `detach(Mim_LR)` before the SR trunk so SR cannot cheat the mimicker.  
4. **Losses:**  
   - `L_sr = L1(ModSwinIR(Mim_LR), HR)`  (main)  
   - `L_deg = ||m ⊙ (LR_w − Mim_LR)||_1`  (geometry via OF-in-loss)  
   - optional light CD/color term if color shift appears  
5. **Inference:** drop the mimicker; feed real LR. Same params/FLOPs as today.
6. **Eval protocol (honest):**  
   - Primary A/B: train → **aligned synthetic** (DIV2K bicubic ×2 or your own aligned crop set) for PSNR.  
   - Secondary: RealSR official test PSNR/SSIM **and** NIQE/PI (test is misaligned).  
7. **8 GB fit:** flow at LR resolution (not ×2); crop 128–192; mimicker on-the-fly; no DCN.

**Expected gain (if residual is the binding constraint):** +0.4–2 dB on aligned-transfer metrics (SwinIR-scale from Mimicked); RealSR-test PSNR may move less because the test set is still misaligned.

### Backup (if residual is large / Mimicked unstable): SDAN-style squared DCN

- Early trunk: concat(LR features, downsample-HR features) → **window-level offsets** (2×H×W, not 18×H×W) → DCN align → residual transformer.  
- Train reference = `resize(HR, LR)`; infer reference = LR itself (self).  
- Use squared offsets + packing attention; **not** vanilla DCN.  
- Cost: DCN at train+infer (or train-only with identity offsets at infer). Heavier on 8 GB than Mimicked.

### Explicit non-goals

- Do not add CX/CoBi as the recon loss.  
- Do not add more HF/amp loss terms before correspondence is fixed.  
- Do not chase RealSR-test PSNR alone to judge the alignment change.

## 6. Bottom line for F3 / compose-next

For RealSR V3 residual-SR, **do not reweight the loss further**.  
Primary intervention: **train-only geometric/color alignment (Mimicked-LR or OF-in-loss)**.  
Backup if residual turns out large on your crops: **squared DCN (SDAN-style)**, never vanilla DCN.  
Verify on an **aligned** eval set; official RealSR test PSNR will under-report the fix.
