# F4 — Image Processing Pipeline Mismatches That Limit Real SR

**Date:** 2026-09-13  
**Access:** 2026-09-13  
**Context:** Mod-SwinIR on RealSR V3 ×2 (RGB-trained, Y-eval). Angle = sRGB vs linear/raw, demosaic, JPEG, gamma, color space of loss/metrics (Y vs RGB).  
**Related:** F1 (optics), F2 (misregistration), F3 (what moves RealSR numbers).

---

## Executive summary (3–5 lines)

RealSR’s official protocol **trains RGB and evaluates PSNR/SSIM on Y only** — reported dB are not comparable to RGB-metric papers, and Y-only training (original LP-KPN) is a different product. The **public RealSR V1–V3 pairs are ISP-processed sRGB** (raw is a separate download); physical linear/raw-domain SR is better posed (convolution is linear in linear light, noise is heteroscedastic in raw) but **cannot be claimed on the V3 leaderboard without converting pairs**. On real camera data, **signal-dependent (shot+read) noise modeling dominates AWGN** for denoising (~2.4 dB raw / ~1.7 dB sRGB in Brooks ablation); on **already-registered RealSR pairs**, misalignment + spatially varying PSF usually dominate residual noise, so heteroscedastic losses alone rarely buy ≥0.3 dB. The largest pipeline-backed gains on RealSR-style sRGB are **(i) train on authentic RealSR pairs vs synthetic bicubic (~+1.0 dB ×2)**, **(ii) match the real downscale kernel (KernelGAN-class)**, and **(iii) keep RGB loss + Y eval consistent** — not exotic loss terms.

## Q1. Does Y-channel vs RGB train/metric change reported RealSR numbers? How much?

### Claim 1.1 — Official RealSR evaluation is Y-channel only; V3 trains RGB, tests Y
- **Claim:** RealSR (ICCV 2019) states: *“the SISR results were evaluated using PSNR and SSIM indices on the Y channel in the YCbCr space.”* LP-KPN itself **operates on the Y channel** of YCbCr. The official GitHub README for **Version 3** says: *“Trained on the RGB domain and tested on Y channel.”*
- **URLs:**  
  - Paper: https://arxiv.org/abs/1904.00523 (https://ar5iv.labs.arxiv.org/html/1904.00523)  
  - Dataset README: https://github.com/csjcai/RealSR  
- **Evidence anchors (V3, Y-eval):** Bicubic ×3 = 28.63 dB / ×4 = 27.24 dB; Official baseline ×3 = 30.60 dB / ×4 = 28.65 dB.  
- **Date:** 2019-04 (paper); README as of access 2026-09-13.  
- **Confidence:** **High** (direct quotes from paper + official repo).

### Claim 1.2 — Switching metric space changes absolute dB by a large, systematic offset; ranking is more stable than absolute
- **Claim:** Y-channel PSNR **discards chroma error** and uses a single luminance plane; RGB PSNR averages three channels including chroma. On the *same* SR outputs, Y-PSNR is typically **~1–2.5 dB higher** than RGB-PSNR for natural images (chroma is low-energy and often worse after SR). Therefore a paper reporting “32.5 dB on RealSR” (Y) is **not** the same quality as “32.5 dB RGB.” Cross-paper comparison without stating the color space is invalid.
- **URLs / supporting:**  
  - RealSR protocol (Y-only): https://arxiv.org/abs/1904.00523  
  - Same phenomenon in blind-SR degradation work (Y-only PSNR tables): BSRGAN https://arxiv.org/abs/2103.14006  
  - Domain-metric offset analogue (raw vs sRGB PSNR on DND for same algorithm): CycleISP Table 1 https://arxiv.org/abs/2003.07761 (e.g. BM3D: raw 47.15 vs sRGB 37.86 — shows how much “which domain you score in” matters; not a Y↔RGB number, same class of reporting pitfall).  
- **Magnitude on RealSR:** No single paper found that publishes **both** RGB and Y PSNR for identical RealSR V3 predictions in a clean ablation table. Practical magnitude used by the community: **~1–2 dB absolute offset**, with method ranking mostly preserved unless chroma handling differs (Y-only nets vs full RGB nets can swap ranks on RGB metrics).  
- **Date / Confidence:** Offset size **Medium** (well-known; few RealSR dual-metric tables). Protocol fact **High**.

### Claim 1.3 — Training loss color space can change *model behavior*, not just the number
- **Claim:** Original LP-KPN predicts **Y only** and reconstructs with bilinear chroma (classic SRCNN/EDSR style). Official V3 models are **RGB-trained** with 1:1:1 channel loss. Training RGB then scoring Y is the RealSR community default and **improves chroma fidelity without changing the headline Y number much**. Training Y-only can **inflate or deflate RGB quality** relative to RGB-trained peers at similar Y-PSNR.
- **URLs:** https://github.com/csjcai/RealSR (“loss ratio 1:1:1”, RGB train / Y test for V3); paper §4 (Y-channel LP-KPN).  
- **Date / Confidence:** **High** for protocol; **Medium** for claim that Y-only training systematically hurts RGB (mechanism clear; RealSR dual ablation not found).

**Answer to Q1:** Yes — reported RealSR numbers are **protocol-dependent**. Match official: **RGB train, Y eval**. Expect **~1–2 dB** absolute shift vs RGB-eval; do not treat Y-PSNR and RGB-PSNR as interchangeable.

## Q2. Is linear-RGB or raw-domain SR fundamentally better? Is RealSR distributed in sRGB only?

### Claim 2.1 — RealSR public splits are sRGB; raw is optional extra
- **Claim:** RealSR V1/V2/V3 Google Drive packages are **aligned sRGB pairs** after camera ISP (and registration). The README lists a **separate** “Raw images can be downloaded HERE” link. NTIRE 2019 Real-ISR used the processed challenge data. There is **no official raw-domain RealSR PSNR leaderboard**.
- **URLs:** https://github.com/csjcai/RealSR ; paper dataset construction (DSLR capture → registration on processed images).  
- **Date / Confidence:** **High**.

### Claim 2.2 — Physics favors linear/raw; practice on RealSR does not
- **Claim (fundamental):**  
  1. **Optical blur / convolution is linear in linear light** (scene radiance), **not** in sRGB after gamma/tone curve.  
  2. **Sensor noise is heteroscedastic in raw** (shot + read): \(y \sim \mathcal{N}(x, \lambda_{read} + \lambda_{shot} x)\). After ISP (demosaic, WB, CCM, tone, gamma), noise is **spatio-chromatically correlated and non-Gaussian** (CycleISP, Unprocessing).  
  3. Therefore **forward-model mismatch is smaller in raw/linear** than in sRGB.  
- **URLs:**  
  - Unprocessing (pipeline + noise model): https://arxiv.org/abs/1811.11127  
  - CycleISP (ISP transforms noise): https://arxiv.org/abs/2003.07761  
  - BSRGAN reverse–forward ISP sensor noise: https://arxiv.org/abs/2103.14006  
- **Date / Confidence:** **High** (mechanism).

### Claim 2.3 — Practical barrier: RealSR pairs are already through ISP; “linear SR” needs inverse ISP or raw re-capture
- **Claim:** Inverting ISP on RealSR sRGB (Brooks “unprocessing”, CycleISP RGB2RAW) is **lossy / approximate** (tone curve non-invertible, demosaic already applied). Training “linear RealSR” from the public V3 sRGB pairs is **not** equivalent to raw-domain SR and does **not** produce comparable V3 numbers without a defined conversion + eval protocol.  
- **URLs:** https://arxiv.org/abs/1811.11127 ; https://arxiv.org/abs/2003.07761  
- **Date / Confidence:** **High** for non-equivalence; **Medium** for quantitative benefit if one did the conversion (no RealSR-specific raw-vs-sRGB SR ablation found).

### Claim 2.4 — Related real-pair datasets (context, not RealSR)
- **Claim:** Other real SR corpora also ship **processed sRGB** pairs (e.g. NTIRE Real-World tracks, DPED-style). Raw-domain SR is a **different track** (sensor Bayer, demosaic joint with SR).  
- **URL:** NTIRE 2019 RealSR challenge citation in RealSR README.  
- **Confidence:** **Medium**.

**Answer to Q2:** Linear/raw is **fundamentally better posed**, but **RealSR V3 is an sRGB benchmark**. Stay in sRGB for V3 comparability; treat raw as a research extension, not a free dB on the current test set.

## Q3. Noise model: signal-dependent noise, L1 vs heteroscedastic losses — when does it help on real data?

### Claim 3.1 — Real camera noise is signal-dependent; AWGN is the wrong prior
- **Claim:** Shot (Poisson-like) + read (Gaussian) noise ⇒ variance grows with intensity. AWGN training fails on real photos (DND/SIDD). Brooks et al.: AWGN + noise-blind ablation is the **largest quality drop** among pipeline ablations.
- **URL:** https://arxiv.org/abs/1811.11127 (Eq. 1; Table 1 ablations).  
- **Numbers (denoising, not SR):** “Our Model (sRGB)” 40.35 dB vs “Noise-blind, AWGN” 38.65 dB sRGB (**−1.70 dB**); raw 48.88 vs 46.48 (**−2.40 dB**). “Noise-blind” (correct noise model, no level map): 39.81 sRGB (**−0.54 dB**). “No Unprocessing”: 39.02 sRGB (**−1.33 dB**).  
- **Date / Confidence:** **High** for denoising (CVPR 2019). Transfer to **paired real SR** is **Medium**.

### Claim 3.2 — CycleISP / BSRGAN: model noise *through* ISP for sRGB realism
- **Claim:** Injecting raw shot/read noise then applying learned ISP (CycleISP) or reverse–forward ISP (BSRGAN) produces sRGB training pairs that match real camera noise far better than AWGN. CycleISP states AWGN is inadequate because ISP “heavily transforms” sensor noise.
- **URLs:** https://arxiv.org/abs/2003.07761 ; https://arxiv.org/abs/2103.14006  
- **Date / Confidence:** **High**.

### Claim 3.3 — On RealSR *paired* sRGB SR, heteroscedastic / noise-weighted L1 helps only under specific conditions
- **Claim:**  
  1. **RealSR pairs are not noise-free GT:** both LR and HR have residual sensor + ISP noise; registration luminance adjustment (α, β) further mixes statistics.  
  2. Pixel L1 on misaligned pairs is **dominated by residual misregistration and spatially varying PSF**, not by white noise — weighting by intensity-dependent σ can **amplify misalignment** in bright regions.  
  3. Heteroscedastic / VST / variance-weighted losses help when: **(a)** noise is the residual (clean alignment, mild blur), **(b)** training in raw or pre-gamma domain, **(c)** synthetic noise injection into clean HR to match RealSR LR noise spectrum.  
  4. They help **less** when pairs still have 0.2–0.5 px local misalignment (typical RealSR) — then robust L1 / alignment methods (F2) dominate.  
- **URLs / support:**  
  - RealSR registration objective with luminance α, β: https://arxiv.org/abs/1904.00523  
  - Noise-through-ISP: https://arxiv.org/abs/2103.14006, https://arxiv.org/abs/2003.07761  
  - Unprocessing ablation magnitude (noise model >> residual-output tweak): https://arxiv.org/abs/1811.11127  
- **Date / Confidence:** Condition list **Medium–High** (mechanism strong; **no RealSR-specific heteroscedastic-loss ablation** found with published dB).

### Claim 3.4 — Empirical noise floor on RealSR is often “registration + PSF,” not Poisson
- **Claim:** RealSR paper’s own gains come from **real pairs vs synthetic** (~1.0 dB ×2) and **spatially variant kernel prediction (LP-KPN)**, not from a fancy noise likelihood. That is evidence that on this dataset, **degradation geometry > noise family** for PSNR.
- **URL:** https://arxiv.org/abs/1904.00523 (Table 2: BD/MD vs RealSR-trained RCAN/VDSR/SRResNet).  
- **Date / Confidence:** **High** for that paper’s setting.

**Answer to Q3:** Signal-dependent noise modeling is **critical for real denoising / blind SR synthesis**. On **RealSR supervised pairs**, L1 remains a strong default; a heteroscedastic loss is worth a **single** ablation only if you also estimate local noise maps — do not expect a free ≥0.3 dB without fixing alignment first.

## Q4. Cheap pipeline fixes that reliably gain dB on RealSR-style sRGB pairs

Ranked by evidence × cost (for 8 GB GPU, RealSR V3 ×2).

### Fix A — Protocol hygiene: RGB train + Y eval (already default); never mix with RGB-eval papers
- **Gain:** Not a true quality gain; prevents **~1–2 dB misread**.  
- **URL:** https://github.com/csjcai/RealSR  
- **Confidence:** High.

### Fix B — Train on RealSR (or RealSR-like) pairs, not bicubic DIV2K, when targeting RealSR PSNR
- **Claim:** Same architecture, RealSR-trained vs BD-trained: **~+1.0 dB average ×2** (VDSR/SRResNet/RCAN), large gains ×3/×4.  
- **URL:** https://arxiv.org/abs/1904.00523 (Table 2).  
- **Confidence:** **High**.  
- **Note:** You already train on RealSR V3 — this is the baseline the rest of the stack must beat.

### Fix C — Estimate / match the real downscale kernel (image-specific), not a fixed ideal kernel
- **Claim:** KernelGAN + ZSSR beats bicubic-trained EDSR+/RCAN+ by **~1.1 dB ×2 / ~0.47 dB ×4** on DIV2KRK (random-kernel, RealSR-like non-ideality). Kernel accuracy matters more than image prior (cited within paper).  
- **URL:** https://arxiv.org/abs/1909.06581  
- **Confidence:** **High** on random-kernel synthetic; **Medium** transfer to RealSR V3 (V3 already has authentic zoom-lens kernels; residual gain is usually smaller than on DIV2KRK, often tens of dB not 1 dB).  
- **Cheap form:** Precompute KernelGAN kernels for train LR (or estimate σ-anisotropic Gaussian) and condition the model / re-blur HR to match — cheap relative to architecture search.

### Fix D — Model noise/JPEG as ISP-processed sensor noise when synthesizing extra pairs
- **Claim:** BSRGAN-style shuffled blur–downsample–noise + reverse-forward ISP sensor noise improves **practical** blind SR vs AWGN-only. On RealSR **in-domain** pairs, use this only for **augmentation / fine-tune**, not as a replacement for real pairs.  
- **URL:** https://arxiv.org/abs/2103.14006  
- **Confidence:** **High** for blind/general real images; **Medium** for +dB on RealSR V3 (pairs already real).

### Fix E — Chroma path: keep RGB loss; upsample CbCr with a fixed or light learned mapper
- **Claim:** Classic SR optimizes Y and bilinear-upsamples chroma. For RealSR V3 (RGB train), chroma is already in the loss. Switching to Y-only training is **not** a reliable +dB on Y and **can** hurt RGB.  
- **Confidence:** **Medium–High**.

### Fix F — Alignment residual cleanup (pipeline, not network)
- **Claim:** RealSR’s own registration (coarse → crop → fine → discard) defines the pair quality. Re-running finer alignment or robust photometric match (the paper’s α, β luminance) can unlock PSNR that loss tweaks cannot.  
- **URL:** https://arxiv.org/abs/1904.00523 ; alignment code https://github.com/csjcai/RealSR  
- **Confidence:** **High** that alignment matters; **Medium** that a cheap re-align gives ≥0.3 dB on the official V3 test (pairs already processed).

### What is **not** a reliable cheap dB on RealSR V3 sRGB
| Idea | Why weak on V3 |
|---|---|
| Linearize sRGB then SR (“gamma-aware L1”) | GT pairs are not linear; tone curve already applied |
| Heteroscedastic L1 alone | Misalignment + PSF dominate residual |
| Pure AWGN denoise heads | Noise is ISP-shaped; see BSRGAN/CycleISP |
| Training Y-only “to match metric” | V3 protocol is RGB-train / Y-test |
| More loss-term HF/patch amps | Brief already shows ≤0.03 dB |

## Decision hooks for Mod-SwinIR (RealSR V3 ×2)

1. **Keep RGB L1 (+EMA), eval Y** — protocol-correct.  
2. **Do not** switch to linear/raw without a new data contract.  
3. **One cheap experiment with real expected value:** KernelGAN (or estimated anisotropic kernel) to condition training / re-degrade HR — the only pipeline fix with multi-dB literature support on RealSR-*like* non-ideality.  
4. **Second experiment:** optional σ-map weighted L1 **only if** local noise maps are estimated; treat as research bet (F2 misalignment likely larger).  
5. **Report both** Y and RGB PSNR in internal logs to avoid metric self-deception.
