## 2. 架构：这一轮最大的杠杆

### 2.1 stride-2 → stride-1：+0.38 dB，参数还少 3.7 倍

原来的 U-Net 用 `in_stride=2 / out_scale=2`（native-LR）：stem 一个 stride-2 卷积降到 LR 尺度，
编码器/解码器全在 LR 跑，最后 pixel-shuffle 抬回 HR。这样最高分辨率只剩一个 stem 卷积和一个 shuffle 卷积，
省 29% FLOPs、显存降 4.5 倍 —— **但代价是 0.38 dB。**

改成 stride-1（整网在 HR 尺度运算）后：

| 配置 | 参数 | Y |
|---|---|---|
| stride-2 `1244 b64`（native-LR） | 18.68M | 33.56 |
| **stride-1 `s1_b32`** | **4.99M** | **33.94** |

**参数少 3.7 倍还高 0.38 dB。** 原因：bicubic 上采样后，HR 尺度上仍然有真实的高频结构需要重建，
用 pixel-shuffle 从 LR 特征"变"出来会丢相位信息。

**代价**：显存 ∝ base（b32 138 / b40 172 / b48 207 / b64 276 MB/样本），硬件效率下降（见 §5）。

### 2.2 容量：不是瓶颈，拐点在 10M 以上

| base | 参数 | Y |
|---|---|---|
| 32 | 4.99M | 33.9445 |
| 40 | 7.58M | 34.0070 |
| 48 | 10.73M | 33.9946 |
| 64 | 18.67M | 34.1083 |
| **128** | **72.53M** | **34.1560** |

- 5.0M → 10.7M：几乎完全平坦（差 0.06 dB）
- 10.7M → 18.7M：+0.11
- **18.7M → 72.5M（参数 ×3.9）：只有 +0.048**

**容量已经饱和。** 继续加参数的边际收益在快速衰减。

### 2.3 通道金字塔不能压平（负结果）

按「激活更多、存/算比更大」的思路做了阶梯实验：

| 形状 | 参数 | 激活 | 存/算 | Y |
|---|---|---|---|---|
| `1244 b64`（当前） | 18.67M | 1901k | 40.2 | **34.1083** |
| `1122_b96` | 11.50M | **2212k** | 46.0 | 34.0364 ↓ |
| `1124_b80` | 18.26M | 1884k | **48.1** | 34.0521 ↓ |

`1122_b96` 激活多 16%、存/算高 14%、参数少 38%、墙钟一样 —— **但 Y 低 0.07。** 剩下三档直接中止。

**结论：U-Net 的通道金字塔本身是有用的，压平它会掉点。**

### 2.4 门控 FFN（已收官：≈打平，关线）

`SpatialGatedFFN`：`proj_in(C→2rC) → depthwise 3×3 → chunk → silu(x1)*x2 → proj_out(rC→C)`，
零初始化，128/64 对齐断言。

**它的定位需要说清楚：**

| 指标 | 数值 | 含义 |
|---|---|---|
| 参数/FLOPs | 1.335 vs 1.333 | **与堆通道完全一样**，没有容量效率优势 |
| 激活/FLOPs | 40.2 → 30.2 | **降低**了存算比 |
| 瞬时中间张量 | 2rC 通道 | 很大 —— 这就是它 OOM 的原因 |

**所以 FFN 卖的不是"更省算力的容量"，而是乘法门控带来的二阶特征交互（表达力）。**

**中途结果（16 对 val）：**

| step | b64 + FFN | b64 无 FFN | 差 |
|---|---|---|---|
| 500 | 32.087 | 33.036 | −0.95 |
| 1500 | 33.297 | 33.766 | −0.47 |
| 3000 | 33.571 | 33.939 | **−0.37** |

全程落后、缓慢收窄。可能的机制：`proj_out` 零初始化使 FFN 初期完全不贡献，卷积路径独自扛梯度，
门控"唤醒"慢；多出的 6M 1×1 参数无归一化，拖慢收敛。

（干扰项：对照组 batch 128，FFN 版因显存只用了 batch 96，同 step 数下少看 25% 样本。）

**官方 100 对最终数（推翻中途读数）**：Y **34.1580** / SSIM 0.9250 / MUSIQ 54.739 / MANIQA 0.3389
—— vs b64 无 FFN 的 34.1083：PSNR **+0.05**、感知略降。16 对 val 的 −0.3 是子集噪声 + batch 混淆。
**判定：≈打平，不值 +33% FLOPs，关线。** 小 val 只能看趋势，定生死要用官方数。

## 3. 扩散：在这个预算下打不过直接回归

- 所有 **flow** 臂 **全部低于 bicubic 地板**（26.8–29.5 dB）
- `latent_reg_flux` 31.12 —— **比它自己零初始化的 31.60 还低**，等于没学到
- 唯一能打的 `pixel_reg`（33.76）其实是**单步回归**（NFE 1），不是采样

### 3.1 但感知指标给出了转折

```
latent_flow_flux：PSNR 28.36（比 bicubic 还低 3.4 dB）
                MUSIQ 50.12（比 E11 的 49.15 还高）
                MANIQA 0.2236（比 bicubic 的 0.2782 还低）
```

**教科书式的 distortion–perception 分离。** 两个感知指标在**回归类**模型上排序完全一致，
在**生成类**模型上彻底分裂。只用 PSNR 会把 flow 判死，只看 MUSIQ 又会把一个模糊生成器判成最好 —— 三者必须一起看。

## 4. 预训练与数据

### 4.1 预训练只值 +0.09 dB

| | Y | 耗时 |
|---|---|---|
| b64 零预训练 | 34.1083 | 1.4h |
| **b64 + 4.8h BSRGAN 预训练** | **34.1889** | **6.1h** |

后训练步数 8000 → 11000 只多 **+0.01 dB**（patience 放到 15 后它自己停了 —— 真收敛）。

### 4.2 为什么？——缺的是多样性，不是更新量

```
390 对训练图 × 10000 步 × batch 96 = 960k 样本 = 2460 个 epoch
```

**每张图被看了 2460 遍。** 所以加步数无益，预训练只改善初始化然后被冲掉。

BSRGAN 的合成退化与 RealSR 的真实相机退化只**部分重合**，所以迁移只值 0.09 而不是 0.5。

### 4.3 加宽比预训练划算

| | Y | 耗时 |
|---|---|---|
| b64 + 4.8h 预训练 | 34.1889 | 6.1h |
| **b128 纯加宽** | 34.1560 | **1.9h** |

**1.9h 几乎追平 6.1h。**

## 5. 4090 上的硬件结论

### 5.1 128 对齐值 1.8× 算力（已实测）

| 配置 | 参数 | GFLOP | **实测算力** |
|---|---|---|---|
| `1244 b64` | 18.67M | 47.23 | 10.3 TFLOPS |
| **`1244 b128`** | **72.53M** | **183.97** | **18.8 TFLOPS** |

注意 **参数/FLOPs 比值三档完全不变（0.394 / 0.394 / 0.396）** —— 收益来自 GEMM 不再走
padding + kernel 降级，**不是存算比变好**。

### 5.2 两条反直觉的观察

- **加大 batch 吞吐封顶**（940 → 1067 samples/s 就不动了），吃满显存和功耗换不来速度
- **收窄通道省 FLOPs 反而慢 2.6 倍**（C=32 时 GEMM 太瘦，10.7 → 4.4 TFLOPS）
- **算力是真瓶颈，但提高算存比救不了** —— 只能靠改架构把 FLOPs 从有用的地方挪走

### 5.3 梯度检查点是 FFN 的必备

b128+FFN 训练稳在 32.51 GB，却会在 step 500 突涨到 47 GB OOM。加 `--grad-ckpt`：
**32.51 → 10.19 GB（3.2×）**，只慢 25%。

另外 `train_pixel` 的 `run_val` 对整张 1000×1400 图做**无分块**前向，大模型会 OOM → 用 `--eval-every 0`。

## 6. 收益排序

**架构 ≫ 容量 > 数据 > 步数**

| 改动 | ΔY | 成本 |
|---|---|---|
| **stride-2 → stride-1** | **+0.38** | 参数少 3.7 倍 |
| 容量 5M → 18.7M | +0.16 | 线性涨 |
| 容量 18.7M → 72.5M | +0.05 | 参数 ×3.9 |
| 4.8h BSRGAN 预训练 | +0.09 | 6× 墙钟 |
| 后训练步数 ×1.4 | +0.01 | — |
| 压平通道金字塔 | **−0.07** | 负收益 |
| 门控 FFN（中途） | *约 −0.3* | +33% FLOPs |

## 7. 结论与建议

1. **最终成绩 Y 34.1988**（`s1_b64` + 预训练 + 后训练），比原版 SwinIR **+1.23 dB**。

2. **性价比最优是 `1244 b128`**：1.9h / 34.1560，逼近花 6.1h 的预训练方案。

3. **这条线已经接近饱和**：容量 ×3.9 只换 +0.05，步数翻倍 +0.01，预训练 +0.09。
   **继续加参数/数据/步数的边际收益都在 0.1 dB 以下。**

4. **剩下的真正瓶颈是数据多样性**（390 张图 × 2460 epoch）。要再往上走，方向不该是"更大的模型"，
   而可能是：更强的正则 / 更好的增强 / 换损失 / 或者引入同域的真实数据。

5. **评估口径的重要教训**：只看 PSNR 会漏掉 distortion–perception 分离。
   本项目已经把 MUSIQ / MANIQA 接入 `eval_official --iqa`，建议后续实验一律带上。
