## Git 状态净化（CNB → 纯 GitHub）

**问题**：仓库被 CNB（cnb.cool）平台的配置和身份污染，93 个提交的作者是机器人账号
`cnb.c8OPGAw7AEA <G1wbxyI2MzOhfGfer7hrDG+cnb.c8OPGAw7AEA@noreply.cnb.cool>`。
`remote.origin.url` 本身是对的（`https://github.com/KiritoFD/SwinIR-refine.git`），
所以这是**配置 + 身份层污染，不是远端指错**。

**清理动作**（顺序重要）

1. 本地 config 清掉：`credential.helper=store --file=/workspace/.git/.git-credentials`、
   三条 `url.https://cnb.cool/.insteadof`、`http.postbuffer`、`push.autosetupremote`、
   `[lfs]` 整段、`branch.main.vscode-merge-base`。
2. `.git/mimocode-project-id`（UUID）与 `refs/notes/remote-stashes`（CNB 平台
   stash 备份指针，只有 1 条）删掉。
3. `git filter-branch -f --env-filter` 同时重写 **author 和 committer**，
   条件用邮箱精确匹配 `@noreply.cnb.cool`（作者名有 `cnb.c8OPGAw7AEA` 和 `Xiaomi MiMo`
   两种变体，只按名字过滤会漏）。
4. 删 `refs/original/*` 备份 → `reflog expire --expire=now --all` → `gc --prune=now`。
   不做这步则 `git log --all` 仍能看到 cnb 作者（全在 original 备份里）。

**验证口径**：`git log --all --format='%ae|%ce' | grep -ci cnb` 必须为 **0**。
只看 `git log`（不含 --all）会误判为已干净。

**推送卡住的真正原因**：清掉 `credential.helper` 后，git 找不到任何凭据，
在非交互环境里会**静默挂在「等待输入用户名/密码」上**，超时也不报错。
`ls-remote` 却能正常返回（只读、走匿名），所以极易误判成网络问题。
- 环境里已有 `GITHUB_TOKEN`（属于 KiritoFD，93 字符），git 不会自动用它。
- 解法：`git -c credential.helper='!f() { echo "username=KiritoFD"; echo "password=$GITHUB_TOKEN"; }; f' push ...`
  配合 `export GIT_TERMINAL_PROMPT=0`（凭据失效时立即报错而非挂住）。
  **用 `-c` 临时传，不要写进 config**，token 不落盘。
- `--force-with-lease=main:<sha>` 的 `<sha>` **必须是完整 40 位**，
  写短哈希直接报 `cannot parse expected object name`。

**结果**：远端 main 从 `842429c` 强制更新为净化后的历史，
作者统计变成 93 × `Xiao Yang <24300240055@m.fudan.edu.cn>` + 上游原作者
（Jingyun Liang 等 56+4+1，保留不动）；tag `v0.0` 也同步重推；
