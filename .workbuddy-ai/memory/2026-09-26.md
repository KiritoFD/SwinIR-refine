### 已从结构自行推导并验证的公式（三式，`base=64`、边长 128/64/32/16）

- 参数量 `P ≈ 9 Σ c_l²`　（3×3 卷积，**与 s 无关**）

- 激活显存 `M ∝ Σ c_l s_l²`　→ 存算比 `I = F / M`

**验证：用 `M ∝ Σ c_l s_l²` 算出的激活数与仓库记录的实测值完全对上** ——
`1244 b64`→1901k（记录 1901k ✓）、`1122 b96`→2212k（✓）、`1124 b80`→1884k（✓）。

### 关键不变量（这才是 1244 的来历）

`1244 = (1,2,4,4)` → 通道 64/128/256/256，**前三级 `c·s = 8192` 恒定**，
于是每级 FLOPs 恰好各占 **30.8% / 30.8% / 30.8% / 7.7%**（算力完美均衡）。
`1128 = (1,1,2,8)` → 通道 64/64/128/512，`c·s` 在 8192 与 4096 之间乱跳，
参数 36.89M 被最宽的 512 级独占，算力分布也失衡。**故 `c ∝ 1/s` 是判据。**

`1128`：36.89M / 9.42 GFLOP / 1083 samples/s　→　`1244`：18.67M / 11.41 GFLOP / 940 samples/s。

**① 仓库的「存/算」**（出现在 `PROGRESS_REPORT.md §2.3`、`2026-09-19.md`）：

存/算 = 激活元素数(k) / GFLOP
1244_b64: 1901/47.23 = 40.2 ✓   1122_b96: 2212/48.09 = 46.0 ✓   1124_b80: 1884/39.17 = 48.1 ✓

反解 batch = 28.08 → 与 DiT-S 记录 batch=28 完全吻合（此前的换算靠这个才闭合）

## 第十一轮返修：Mamba 参数量标进表（用户：`mamba的参数量也标上去啊`）

### 参数量来源（这次是**解析推导 + 实测校验**，不是抄文档）

`exp/MAMBA_ARM.md` 只记了「c128 4×4 = 2.75M」「c256 4×4 = 10.48M」，
**c96 矩阵臂的具体参数量文档里没有**。用 `experiments/smoke_mamba/ckpt_last.pt`
（dim32 / 2RG×2 / N16 / E2 / scale1，实测 65763 参数）逐项反推，得到**完全吻合的闭式**：

```python
# 逐项（全部对得上 smoke ckpt：stem 896 / ln 64 / dwconv 320 / proj 1056 / core 9920 / out_conv 867）
core(d,N,E,dc=4): di=int(E*d); dtr=max(1,ceil(d/16))
    = d*2*di            # in_proj(no bias)
    + di*dc + di        # conv1d(depthwise)
    + di*(dtr+2N)       # x_proj(no bias)
    + dtr*di + di       # dt_proj(bias)
    + di*N + di + di*d  # A_log + D + out_proj
vss(d,N,E) = 2d + (9d+d) + core(d,N,E) + (d*d+d)
rg(d,dep,N,E) = dep*vss + (d*d*9 + d)     # ⚠️ RG.conv 是 d×d×3×3 全卷积，不是 depthwise
mamba(dim,g,dep,N,E,inc=3,scale=2) = 3*dim*9+dim + g*rg + 2*dim + dim*(3*scale²)*9 + 3*scale²
```
校验：`mamba(32,2,2,16,2,scale=1)=65763` **精确等于实测** ✓；
`mamba(128,4,4,16,2)=2.7605M` ≈ 文档 2.75M ✓；`mamba(256,4,4,16,2)=10.5016M` ≈ 文档 10.48M ✓。
