# 2026-09-20

## Mamba 臂：已终结（明确负结果）

- `mamba_c128`（scale=2）：**Y 32.5492 / SSIM 0.9029 / MUSIQ 45.902 / MANIQA 0.2989**
  比 U-Net b64（34.1083）低 **1.56 dB**，比旧基线 E11（33.4655）还低 0.92 dB，只比 bicubic 高 0.82。
- M2 `mamba_c256` 跑到 step 350/1000（18 s/step）后**按用户要求砍掉**。

**我实现了窗口化 stride-1 Mamba 试图救它**（`--ssm-window` / `--ssm-shift`），实测：
- stride-1 + window32 + shift：batch 64 / 45.8 GB / **14.7 s/step = 71k tokens/s**
- U-Net b64 stride-1：batch 96 / 29.9 GB / 0.51 s/step = **3.06M tokens/s**
- **每 token 慢 43 倍**；压缩状态（expand=1 d_state=4/8）后直接 OOM

**窗口化没用的原因**：只增加并行度，不改每 token 成本。真正的约束是
**扫描状态 d_inner×d_state = 16 KB/token（卷积约 0.02 KB）**，不是序列长度。
吞吐恒定 ~4.4 samples/s → 512k 样本需 32h，锚点预算 1.28M 需 81h。**不可行。**

**结论：Mamba 是 HR 像素空间超分的错误算子。** 它的线性项常数就极大，连 n² 都不是。
详细实测写在 `exp/MAMBA_ARM.md` 的「结论」一节。

跨窗混采用 **pad + 半窗偏移**，不用 cyclic roll（roll 会把远处 token 放进同一条扫描，衰减跨接缝泄漏）。
零初始化不变式已验证保持（max|out| = 0.000e+00）。
